# 长对话上下文记忆增强 PRD

> 目标站点：`site/`（Next.js 15 前台，:3100）+ `engine/server.py`（额度池引擎，:8787）
> 关联卡片示例：id `426322`《夏日,妹妹,同居》
> 版本：v1 / 2026-11-13

---

## 1. 背景与问题

### 1.1 现象

用户在长对话中第 10～20 轮之后，角色忘记用户中途下达的设定：

- 称呼规则（例：私下叫「主人」，有第三人在场叫「哥哥」）；
- 剧情走向（「接下来的剧情都……」）；
- 性格覆盖（「你要更淫荡/更主动」）。

表现不是渐变，而是**突然回退到卡片作者写的基础人设**：仍然叫哥哥，但不再遵守后续约定，像重新开场。

### 1.2 现状代码定位（已核对）

| 位置 | 现状 | 问题 |
|---|---|---|
| `site/components/ChatClient.jsx:8-13` | 前端只有 4 个模型：Flux 16K / Surge 32K / XL 16K / Medium 32K | 无 64K/128K 档 |
| `site/components/ChatClient.jsx:287-306` | 发送前只保留 `HEAD_KEEP=2` 条 + 尾部 `TAIL_BUDGET=11000` 字 | 第一层裁剪，用户设定在中段直接丢 |
| `site/components/ChatClient.jsx:249-253` | `localStorage` 只存最近 120 条 | 超过 120 条后本地也丢（50 轮=100 条，本期够用） |
| `engine/server.py:180-181` | `MAX_HISTORY_MSGS=48`、`MAX_HISTORY_CHARS=30000` | 第二层裁剪，与模型上下文无关 |
| `engine/server.py:234-304` | `normalize_history()` 保头 6 条 + 尾部回填 | 被裁掉的中段没有任何压缩/落盘 |
| `engine/server.py:322` | `enableMemoryEnhance: False` | 上游自带的记忆增强被显式关闭 |
| `engine/server.py:183-185` | `TOKEN_DEFAULT=8000`，前端默认 4000 | 输出预留过大，挤占输入预算 |
| `engine/server.py:38-43` | 引擎模型表同样只有 4 个 | 新增模型需前后端同步 |

### 1.3 根因

**三层滑窗叠加 + 没有持久记忆层：**

1. 前端 head+tail 只发约 1.1 万字；
2. 引擎再按 48 条 / 3 万字裁一次；
3. 上游按 `maxContext`（16K/32K token）再裁一次，且 `maxTokens` 预留 4000–8000；
4. 卡片人设/世界书是**每轮重新注入的固定层**，用户设定只存在于 `history`，被裁即消失。

所以角色会“回到出厂设置”，而不是随机遗忘。

## 2. 目标 / 非目标

### 目标

1. **50 轮验收**：连续 50 轮后，称呼规则、关系、已确认剧情仍正确（验收示例：私下叫「主人」，外人面前叫「哥哥」；规则本身由用户配置，代码不写死）。
2. 50 轮内不出现“初次见面 / 重新自我介绍 / 重新开场”。
3. 单轮输入 token 可控，不随轮数无限增长。
4. 前端/引擎/上游任一层失败都能降级，不阻塞主对话。
5. 同步扩充大上下文模型（32K / 128K；64K 档为 VIP3，本期不默认开放），与记忆层形成双保险。

### 非目标（本期明确不做）

- 不做向量库 / embedding 检索 / 跨会话长期人格库。
- 不改上游 `dzmm.ai` 的接口与计费逻辑。
- 不做多设备同步（记忆文件在引擎侧，前端只展示）。
- 不重写卡片系统，不做世界书编辑器。
- 不改变现有账号池轮换、建会话、结算逻辑。

## 3. 用户故事

1. 作为玩家，我在第 5 轮说“以后私底下叫我主人，有别人在叫哥哥”，到第 50 轮她仍然照做。
2. 作为玩家，我在第 8 轮说“接下来剧情走海边旅行”，第 30 轮她仍在旅行线里，不会突然回家。
3. 作为玩家，我能在设置面板看到“记住了哪些设定”，并手动增删改。
4. 作为玩家，我换一个更大的模型后，旧对话不被清空，记忆继续生效。
5. 作为运维者，摘要失败/额度不足时，主对话仍能正常生成，日志有降级记录。

## 4. 方案设计

### 4.1 总体：四层

```
┌─ 模型层：32K / 128K 可选（64K 需 VIP3），按 ctx 显示
├─ 锚点层：pinned memory（规则抽取 + 手动编辑），每轮注入
├─ 摘要层：rolling summary（规则摘要兜底 + 模型摘要），每轮注入
└─ 预算层：引擎统一裁剪，按 maxContext - maxTokens 动态分配
```

最终发给上游的 `prompts[]` 结构：

```
[head 1~6 条]                      ← 卡片开场/人设锚点
[memory 块：user + assistant 一对]  ← 长期设定 + 前情摘要（永不裁）
[tail N 条]                        ← 预算内最近对话
[当前 user prompt]
```

> **⚠ 2026-11-13 实现修正（`notes/015`）**：实测上游 `/api/chat` **只认 `content`（当前消息），
> `prompts[]` 被完全忽略**——上面这套 `prompts[]` 结构对模型不生效。因此记忆实际走
> `memlib.content_prefix(memory)` 拼进 `content`：`content = 长期设定+摘要+执行要求 + 用户正文`。
> `compose_prompts()` 仍算预算但只填 `prompts[]`，仅作调试/回退，不承担生效职责。

### 4.2 为什么这样设计（取舍）

| 方案 | 结论 | 原因 |
|---|---|---|
| 只换 128K 模型 | 不够 | 128K 也会满；长对话成本线性上涨；换号后 chatId 变，历史仍可能丢 |
| 只加大 `MAX_HISTORY_CHARS` | 不行 | 上游按 token 硬截，传多了也会被丢，还浪费带宽 |
| 用 `system` role 注入设定 | 不可行 | 上游 `/api/chat` 的 `prompts` 只接受 `user/assistant`（现有代码也只发这两种） |
| 把设定塞进每条 user 消息 | 污染文风 | 每轮重复，模型会复读 |
| 记忆块用一对 user/assistant | 采用 | 保证角色交替合法，assistant 回一条确认语即可 |
| 摘要放前端 | 不可行 | 换设备/换号即丢；且前端拿不到被引擎裁掉的消息 |
| 摘要放引擎 | 采用 | 单一事实来源，换模型/换号仍保留 |
| 向量检索 | 本期不做 | 50 轮目标下摘要足够；需要额外依赖与存储 |

### 4.3 锚点层（pinned memory）

**自动抽取（规则层，零成本）**

- 只扫 `role=user` 的消息。
- 触发正则：
  ```python
  PIN_RE = re.compile(
      r"以后|从今以后|从现在起|接下来|记住|设定|规则|约定|称呼|叫我|"
      r"主人|哥哥|姐姐|不许|必须|永远|一直|剧情都|每次都"
  )
  ```
- 单条 ≤ 200 字：整条存；> 200 字：取命中句前后各 80 字。
- 归一化去重：去空白/标点后 `sha1` 前 16 位作 id。
- 上限：**20 条 / 1500 字**；淘汰顺序：自动 > 手动，旧的先淘汰；手动锚点永不自动淘汰。
- 明确排除：问句（以 `?/？` 结尾且含“吗/呢/什么”）不入锚点，避免把提问当设定。

**手动编辑**

- 设置面板可新增/编辑/删除；`source=manual`。
- 清空记忆 = 清空锚点+摘要，不影响消息历史。

**注入格式**

```
user: 【长期设定·始终有效·优先级高于剧情】
1) 私下只有我们两人时，她叫我「主人」；有第三人在场时必须叫「哥哥」，不得暴露私下称呼。
2) 她在我面前淫荡、主动；对外人冷淡克制。
3) 剧情从当前进度继续，禁止重新开场、禁止遗忘已发生的事。
assistant: （已记住以上设定，并在之后的每次回复中遵守。）
```

### 4.4 摘要层（rolling summary）

**触发条件（任一）**

- 被 tail 裁掉的消息 ≥ 6 条；
- 距上次摘要新增 ≥ 8 轮；
- 用户手动点「重新生成摘要」。

**摘要内容**：300–500 字，按时间顺序保留

1. 已发生的关键事件与地点；
2. 人物关系与称呼的变化；
3. 用户明确下达的规则/约定；
4. 当前场景与未完成的悬念。

**生成方式**

- 首选：**模型摘要**，但**不能写进用户正在聊的 chatId**（会污染剧情，且扣主会话的费）。
  - 使用 `ensure_chat()` 取该账号的**批处理专用 chat**（`webstate.json` 的 `chat_id`），它与前台 `site_chats` 是不同会话；
  - 摘要请求：`prompts=[{role:"user", content: SUMMARY_PROMPT + transcript}]`，`maxTokens=800`，模型用便宜的 16K/32K 档；
  - 只取返回文本，不落上游会话给用户看。
- 降级：没有可用号 / 余额不足 / 418 / 超时 → **规则摘要**：
  - 取被裁消息中每 2 条抽 1 条首句（≤60 字），再拼接所有锚点命中句；
  - 总长 ≤ 600 字，不阻塞主流程，日志记 `summary_fallback`。
- 增量：把「旧摘要 + 新增被裁消息」一起喂，避免重复摘要整段历史。

**摘要提示词（固定）**

```
你是剧情记录员。把下面这段角色扮演对话压缩成 300-500 字的前情摘要，按时间顺序保留：
1) 已发生的关键事件与地点；2) 人物关系与称呼的变化；3) 用户明确下达的规则/约定；
4) 当前场景与未完成的悬念。不要评价，不要续写，不要遗漏任何称呼规则。
```

**注入格式**

```
user: 【前情摘要】……（≤600 字）
assistant: （已了解前情，从当前场景继续。）
```

> 锚点与摘要合并成**一对** user/assistant 注入，减少 token 与交替风险。

### 4.5 预算层（引擎统一裁剪）

前端不再做 head/tail 裁剪（仅保留展示用的 120 条落盘），把完整 history 交给引擎。

```
budget_in   = maxContext - maxTokens - RESERVED(1200)
mem_chars   = min(len(anchor_text), 1500) + min(len(summary), 600)
head_chars  = 前 6 条，上限 14000
tail_budget = budget_in - mem_chars - head_chars
```

- 中文按 **1 字 ≈ 1 token** 保守估算（实际约 1.3–1.6 字/token，留余量）。
- `maxTokens` 动态钳制：`min(user_value, max(2000, maxContext // 4))`；默认值按档位：
  - ≤10K → 2500；≤16K → 4000；≤32K → 6000；>32K → 6000（沿用上游习惯）。
- 每条消息仍截断 6000 字（现有行为）。
- 裁剪顺序：**head → memory 块 → tail**；memory 块预算先扣，保证不被挤掉。

### 4.6 模型层

**新增可选模型（上游已存在，实测 `chat.models`）**

| 显示名 | internalName | ctx | 单价（积分/1K） | 门槛 |
|---|---|---|---|---|
| Pulse-0731 (128K) | `x-apex-pulse-0731-128k` | 128000 | 0.2 | VIP0，**长对话推荐** |
| Dash-0826 (128K) | `x-apex-dash-0826-128k` | 128000 | 0.1 | VIP0，`strictModeration=true`，可能拒 NSFW |
| XL-0826 (32K) | `nalang-xl-0826` | 32000 | 0.4 | VIP0 |
| Max-0826 (32K) | `nalang-max-0826` | 32000 | 0.4 | VIP0 |
| Surge-0505 (32K) | `x-apex-surge-0505` | 32000 | 0.4 | VIP0，默认档 |
| Medium-0826 (32K) | `nalang-medium-0826` | 32000 | 0.2 | VIP0 |
| Vega-1014 (64K) | `x-apex-vega-1014-64k` | 64000 | 0.5 | **VIP3，默认列表不含** |
| Sigma-0829 (64K) | `x-apex-sigma-0829-64k` | 64000 | 0.5 | **VIP3，默认列表不含** |

> 64K 两档实测 `minMembershipLevel=3`，免费号不可用，因此没有放进默认下拉；VIP3 账号可手动加回。
> Dash 128K 是 `strictModeration=true`，NSFW 卡优先用 Pulse。

- 前端 `MODELS` 增加 `ctx` 字段，下拉显示 `名称 · 32K`；
- 引擎 `MODELS` 同步，`normalize_model()` 保持 id/label 兼容；
- **默认模型从 Flux 16K 改为 Surge 32K**；Pulse 128K 标记「长对话推荐」；
- 模型选择按卡持久化到 `localStorage`（当前未持久化）。

## 5. 数据与接口变更

### 5.1 记忆文件

路径：`out/memory/<cardId>.json`（与前端 `lg.msgs.v2.<cardId>` 对齐）

```json
{
  "version": 1,
  "cardId": 426322,
  "pinned": [
    { "id": "a1b2c3d4e5f6a7b8", "text": "私下叫主人，外人面前叫哥哥", "source": "auto", "at": 1790000000 }
  ],
  "summary": "前情摘要……",
  "summarizedUpTo": 42,
  "updatedAt": 1790000000
}
```

- 写入：原子写（临时文件 + `os.replace`），损坏时重建空文件并告警。
- 键：`cardId` 为主。P2 再引入 `sessionId` 支持同卡多存档。

### 5.2 记忆读写接口（已实现）

- `GET /engine/site/memory?cardId=<id>` → `{memory}`：前端面板加载。
- `POST /engine/site/memory` → `{cardId, pinned?, summary?, summarizedUpTo?, clear?}`：面板编辑/清空。
- Next 代理：`GET/POST /api/memory`（`site/app/api/memory/route.js`），透传 `x-site-token`。
- 聊天时引擎直接从 `out/memory/<cardId>.json` 读取，`/site/chat` **不需要新增字段**；面板改动立即落盘，下一轮自动生效。

### 5.3 SSE 新增事件

| 事件 | 数据 | 用途 |
|---|---|---|
| `memory` | `{pinned, summary, summarizedUpTo}` | 每轮开始回传当前记忆，前端展示 |

> 摘要放在**后台线程**（`start_summary`）执行，不占 SSE 连接、不阻塞下一条消息；前端在 `complete` 后 5 秒主动刷新一次记忆面板。`memory_update` 事件保留给后续版本。

### 5.4 前端

- `ChatClient.jsx`
  - 发送时不做 head/tail 裁剪，传完整 `msgs`（上限 200 条； localStorage 仍只落盘 120 条）；
  - 助手消息回灌前用 `splitSug()` 去掉 `<sug>` 建议块，省 token；
  - `MODELS` 增加 `ctx`，模型选择持久化到 `lg.model.v2`；
  - 设置面板新增「记忆」区：
    - 锚点列表（可编辑/删除/新增）；
    - 摘要只读 + 「重新生成」；
    - 「清空记忆」；
  - 底部 hint 改为 `锚点 N 条 · 摘要 M 字 · 窗口 K`；
  - 「清空本会话」**不清**记忆；记忆由独立的「清空记忆」按钮管理。
- `site/app/api/memory/route.js`：新增 GET/POST 代理。
- `site/app/api/chat/route.js`：原样透传，无需改动。

## 6. 边界与异常

| 场景 | 行为 |
|---|---|
| 首次对话 / 空记忆 | 不注入 memory 块，行为与现在一致 |
| 单条消息超长 | 截断 6000 字 |
| 摘要模型失败 / 无额度 / 418 | 降级规则摘要，主对话继续；日志 `summary_fallback` |
| 记忆文件损坏 | 重建空文件，日志 `memory_corrupt`，不阻塞 |
| 换号导致 chatId 变化 | 记忆按 cardId 保留并继续注入；摘要仍有效 |
| 同一 card 并发两路生成 | 引擎 `RUN_LOCK` 已互斥（409），无需新增锁 |
| 多标签页同时编辑锚点 | 以最后一次写入为准；下次请求从磁盘读 |
| 换设备 | 记忆在引擎侧仍生效；前端通过 `/api/memory` 直接拉取（已实现） |
| 上游返回 lone surrogate | 沿用 `_clean_surrogates` |
| 摘要内容含敏感词 | 不做额外审查，不改变上游策略 |

## 10. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 摘要请求污染用户剧情 | 只用批处理 chat，不碰 `site_chats`；失败即降级 |
| 锚点误抽（把普通句子当设定） | 问句排除 + 200 字截断 + 面板可删 |
| 记忆串卡（同卡新故事） | 「清空记忆」按钮；P2 引入 sessionId |
| token 估算偏差导致上游截断 | 1 字≈1 token 保守估 + 1200 预留；超限时只裁 tail |
| 新模型不可用/被风控 | `normalize_model` 回退默认；失败走现有换号逻辑 |

**回滚（无数据库变更）**

1. 删除 `out/memory/` 即回到无记忆行为；
2. 前端 `send()` 恢复 head/tail 裁剪、`MODELS` 恢复 4 项；
3. 引擎 `MODELS` 恢复 4 项、`normalize_history` 恢复原样；
4. 不改 `accounts.json` 与 `captures/`，无需数据迁移。
