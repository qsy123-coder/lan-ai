# notes/004 — 多会话并发受阻：新会话 `/api/chat` 一律 403（2026-11-07 00:00–00:20）

## 1. 结论

**并发竞态这条路，在 free 档位上打不动**：`/api/chat` 只对"老会话"放行，新建会话一律 `403`（空 body），
而同一个 body、同一套头、只把 `chatId` 换成老会话就是 `200`。服务端按 chatId 做了额外限制。

## 2. 证据链（同一 cookie、同一 headers、同一 body 模板）

| 实验 | chatId | 结果 |
|---|---|---|
| A 原样 body | `7010f1c0…`（23:37 创建，有完整对话） | **200**，正常 SSE |
| B 新会话 | `963ddfa8…`（createByCard 新建） | 403 |
| C 新会话 + referer 指向老会话 | `963ddfa8…` | 403 |
| D 老会话 + referer 改成 `/chat` | `7010f1c0…` | **200** |
| E 新会话 + referer `/chat` | `963ddfa8…` | 403 |

补充排除项（都做过，仍 403）：

- `chat.getMessages` 200、`chat.getSettings` 200、`card.getForChat` 200 —— 先"暖场"无用。
- 直接 `GET /chat?c=<新会话>`（SSR 页面 200，254 KB）—— 打开页面无用。
- `chat.listAll` 里新会话**排在第一**（17 条全在），不是白名单问题。
- 换干净出口（瑞士 01，404 干净）后重建会话再打 —— 仍 403，与 IP/闸门无关。

## 3. 最可能的解释

free 档位**只允许在单个会话里生成**（体验会话），其余会话创建得出来、消息读得到，但生成被 403 拦。
另一种可能是新会话要求某种"卡片版本绑定/初始生成"，但 `card.getForChat` + `getMessages` 都没解开。
无论哪种，**结果是同一个：拿不到 N 个可并发的会话**，余额检查的原子性在这个账号上无法验证。
